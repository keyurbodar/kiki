# features/composer

Owner: B4. Scope: composer behaviour: Lexical plugins, mentions, slash menu, attachments, footer, context meter, queue.

One directory per unit. A unit directory holds its component, its tests and an `index.ts`. Route files under `src/routes/` import from here; nothing here imports from `src/routes/`. See [CONTRIBUTING.md](../../../CONTRIBUTING.md).

| Unit                  | Capy source                                                                            | Exports                                                                                                                                                                                                                                                                                                                                |
| --------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `composer-footer`     | `features/thread/composer-footer.tsx`, `ui/status-trigger.tsx#FooterTrigger`           | `ComposerFooter` (machine and branch chips left, meter slot right), `MachineTrigger` and its menu (summary, setup progress, resources, Run Setup again, Wake machine), `BranchTrigger`, handoff rows (`DeviceTargetsSub`, `MoveToCloudRow`, `CancelMoveRow`), `FooterTrigger`, `StatusDot`, and the pure label helpers in `machine.ts` |
| `context-meter`       | `features/thread/context-meter.tsx`                                                    | `ContextMeter` (reads `events/context-usage` through `contextUsageAtom`), `ContextMeterControl` (ring, tooltip, popover or phone drawer, segment breakdown, Compact at row), `MeterBar`, formatting in `format.ts`                                                                                                                     |
| `message-queue`       | `features/thread/message-queue.tsx`, the `queued-marker` row of the thread status line | `MessageQueue`, `QueueRow`, `QueuedMarker`, `useQueueActions` (serialised actions that wait for optimistic rows), `useQueueTransitions` (exit animations), `useMessageQueueApi` (Send now via `messages/:eventId/send-now`, Discard and Edit via `messages/:eventId/cancel`)                                                           |
| `upload-send-failure` | stub                                                                                   | `UploadSendFailure`                                                                                                                                                                                                                                                                                                                    |

The footer takes view models rather than reading machine and handoff data itself, because those groups are not decoded yet. The thread view (B7) builds a `FooterMachine` and passes handoff rows composed from the exported row components.

Dev preview: `/__composer-footer` (dev builds only, `?mode=light|dark`).
